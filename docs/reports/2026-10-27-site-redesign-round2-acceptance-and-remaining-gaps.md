## Principle Alignment

- CKB native: distinguish an item from its containing cell, occupied capacity from data length, physical lock ownership from a named party, and a current executable binding from historical family attribution.
- Local first: the remaining rounds are API read-time and frontend work. They add no per-block/per-transaction writes, schema, bulk replay, header-prefix scan, or indexer synchronization work. The API remains read-only; this lane changes documentation and acceptance artifacts only.
- Exactness: complete owner/entity scope precedes pagination; amounts stay integer strings/BigInt. Missing or contradictory evidence is visible, not replaced by zero. A fixture is an explicit test scope, not a claim about the present live chain.
- Agent friendly: each remaining task below has a source entry point, a concrete deliverable, and an acceptance gate. Fixes belong with their owner; this lane does not patch around API defects in UI fixtures.
